# 세이프레이더 SafeRadar 기획서 (접수양식 02장 초안)

> 팀명·대표자·연락처 등 참가자 정보는 **접수양식 01에 기재**합니다(이 문서에는 쓰지 않음).
> 이 문서의 "동작"은 모두 **Pleos Connect 에뮬레이터, 가상 차량·가상 주행(시연 모드), 로컬 테스트 서버** 기준입니다. 실차·실도로·실서버 결과가 아닙니다.
> 표기: **[기획 가정]** = 기획 원문의 가정(검증하지 않음), **[구현]** = 코드·테스트로 확인, **[미구현/미검증]** = 6장 한계 참조.

## 1. 앱 한 줄 소개

주변 차량의 위험 운전을 미리 알 방법이 없는 문제를, 내 주행을 점수로 돌아보고 동의한 운전자끼리 익명으로 근접 경고를 주고받는 방어운전 앱으로 풀어 줍니다.

## 2. 기획 배경

- **주목한 순간**: 내가 조심해도 옆 차로의 급차선변경·급가속·급제동 차량 때문에 위험해지는 순간이 있고, 운전자는 주변 차량의 운전 성향을 미리 알 방법이 없습니다. (기획 원문의 문제 인식)
- **왜 차량인가**: 차량은 속도·기어·브레이크·조향각·방향지시등 신호를 직접 알고 있어 스마트폰 센서 없이 운전 습관을 계산할 수 있습니다. (정확도가 스마트폰보다 높다는 원문 주장은 검증하지 않았습니다.)
- **주행 안전 관점**: 주행 중에는 조작 없는 읽기 전용 화면과 음성·짧은 배너만 쓰고, 점수 확인·설정은 정차 중에만 하도록 설계했습니다. 이 앱은 운전 보조 도구이며 전방 주시와 안전 운전은 운전자의 책임입니다.

## 3. 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 상태 |
|---|---|---|
| 위험 이벤트 감지 | 급감속(≥3.5m/s²) · 급가속(≥3.0m/s²) · 방향지시등 없는 차로변경(50km/h 이상, 2초 내 조향 변동 ≥6°, 최근 4초 내 지시등 없음) · 고속 지속(130km/h 이상 10초) · 급격한 고속 진입(10초 내 +40km/h, 100km/h 이상) | [구현] 임계값은 **미검증 초기값** |
| 점수·리포트 | 이벤트 횟수x가중치를 주행거리로 환산해 0~100점. 주차(P단/정차 30초) 시 오늘의 점수·감점 구간·개선 팁, 주간 추이, 배지 4종. 기록은 최근 60회, 이 기기에만 저장 | [구현] 가중치는 미검증 |
| 근접 경고(옵트인) | 동의 후 주행 중(20km/h 이상) 3초마다 서버에 익명 번호·약 150m 격자·방향·등급(위험 등급일 때만 주된 위험 유형 포함)을 보내고, 같은 방향 약 200m(격자 오차 포함 300m) 이내 위험 등급 차량이 있으면 음성·상단 3초 배너 | [구현] 로컬 서버·시연 기준 |
| 시연 모드 | 설정에서 시작(정차 중). 가상 주행(약 2분 10초)과 가상 위험 차량 2대를 앱 안에서 주입. '시연' 배지 표시, 서버 전송·기록 저장 없음 | [구현] |
| 백그라운드 수집 | 위치 유형 포그라운드 서비스(설정에서 끌 수 있음). 시동과 함께 자동 실행은 **아님** | [구현] 실동작 [미검증] |

**차량 특화 요소**
- Pleos Vehicle SDK의 차속·기어·브레이크 페달·조향각·방향지시등 신호와 위치(FusedLocation)로 이벤트를 판단합니다.
- 주행/정차에 따라 분리되는 UX, 음성(TTS) 경고. 방향지시등 신호가 한 번도 수신되지 않으면 차로변경은 판단하지 않습니다(알 수 없음을 꺼짐으로 보지 않음).

### 주행 안전 설계
- **DO 선언**: `distractionOptimized=true`.
- **정차/주행 UX 분리**: 주행 중은 이번 주행 점수·이벤트 수·공유 상태만 보이는 읽기 전용 한 화면(스크롤·입력 없음)과 상단 3초 배너. 정차 시 오늘/주간·배지/근접 경고/설정 4탭.
- **주행 중 조작 차단**: 모든 상태 변경은 UI와 컨트롤러 양쪽에서 주행 중 차단(`parkedOnly`) — 단위 테스트와 에뮬레이터(D 40km/h 에서 설정 위치 탭 시 팝업·상태 변화 없음, 2026-11-11 후속 검증 7번)로 확인했고, 실차 확인은 없습니다(6장).
- 경고 빈도 제한: 같은 상황 30초, 모든 경고 8초 간격. 정차 중에는 경고하지 않음. 음성 인식(마이크)은 사용하지 않습니다.

### 개인정보 설계 (옵트인)
- 근접 경고는 **기본 꺼짐**이며 켜기 전에는 위치를 어디로도 보내지 않습니다.
- **보내는 것**: 익명 번호(무작위 128비트, 10분마다 교체, 저장 안 함) · 대략 위치(Geohash 7자리, 약 153m x 121m 격자) · 진행 방향(8방위) · 최근 10분 이벤트 기반 양호/주의/위험 등급, 그리고 위험 등급일 때만 주된 위험 유형.
- **보내지 않는 것**: 이름·계정·기기 번호·차량번호·정확한 좌표·속도·주행 점수/기록·음성.
- **정직한 고지**: 이동 경로를 저장하지는 않지만 **같은 번호로 최대 10분간 연속된 대략 위치(약 150m 격자)를 보내며, 서버는 접속 IP를 볼 수 있습니다.** 10분 교체 ID라도 위치 이동으로 서버가 교체 전후를 연결할 수 있어 서버 신뢰를 전제로 합니다.
- **서버 보관**: 이 앱이 설계상 연결하는 서버(**로컬 테스트 서버 기준**)는 위치를 메모리에 15초만 두고 디스크·로그에 남기지 않습니다. 앱은 임의의 https 서버에도 연결할 수 있어 그 서버의 정책은 별도입니다.
- **철회**: 근접 경고 탭의 스위치를 끄면 즉시 전송 중단, 익명 번호 폐기, 서버에 내 항목 삭제 요청(best effort). 설정에서 로컬 기록 모두 삭제 가능.
- release APK의 기본 서버 주소는 `127.0.0.1:8765`(개발·시연용 로컬 서버, 루프백)입니다. **호스트 PC에서 서버를 띄우고 `adb reverse` 로 연결하면 동의 후 실제로 서버와 주고받으며 근접 경고가 서버를 거쳐 옵니다**(2026-11-11 최종 서명본 점검에서 보고 도착·근접 경고 배너/TTS 호출·정차 시 중단·철회 시 중단을 에뮬레이터에서 확인). 서버가 없으면 '서버에 연결하지 못했어요' 안내만 나오고 아무것도 전송되지 않으며, 전체 흐름은 설정 > 시연 모드에서 볼 수 있습니다. 동의 안내에 전송 대상 주소를 표시합니다.

## 4. 주요 사용 시나리오

**사용자**: 고속도로 출퇴근 운전자, 초보 운전자, 가족 운전자 (기획 원문의 타깃)

**이용 흐름 (에뮬레이터 시연 모드 기준)**
1. 앱 실행 후 정차 중 설정에서 시연을 시작하면 가상 주행이 시작됩니다(화면에 '시연' 배지).
2. 시연 중 이벤트가 누적됩니다(검증에서 5회 관찰, 서버 전송 없음 문구 표시). 가상 위험 차량이 가까이 오면 "왼쪽 뒤에 …차량이 있습니다" 형태로 음성·배너 안내가 나오도록 구현했습니다(배너 문구는 접근성 트리로 확인, 실제 음성은 미확인).
3. 시연이 끝나면 리포트(시연 점수 72, 이벤트 5종 각 1회)가 나오며 저장되지 않습니다.
4. 실신호 경로: 가상 콘솔로 조향각을 바꿔 방향지시등 없는 차로변경이 집계되고, 정차 후 리포트(예: 84점·2회, 개선 팁)가 표시됩니다.
5. 시동과 함께 자동 실행하는 방식은 구현하지 않았고, 그 이유는 5장 표에 적었습니다.

## 5. 개발 계획

**개발 환경**: Pleos Connect 에뮬레이터(AAOS 기반), Kotlin, Jetpack Compose, 최소 SDK 28 / target 35. 앱 ID `com.hmgcarapp.saferadar`. 점수·이벤트 로직은 순수 도메인 모듈로 분리해 단위 테스트합니다.

**Pleos SDK 사용**

| SDK | 사용처 |
|---|---|
| Vehicle | 차속, 기어(주행/정차), 브레이크 페달, 조향각, 방향지시등 |
| FusedLocation | 현재 위치(Geohash 계산, 주행 판정 보조) |
| NaviHelper | 현재 도로 제한속도 수신(`onCurrentRoadSpeedLimit`, 읽기 전용; 에뮬레이터에서 콜백은 수신되나 값이 모두 0, 0이 아닌 값은 미관측) |
| TextToSpeech | 근접 경고·리포트 음성 안내 |

Pleos 디자인시스템 컴포넌트와 주행 규제(UX 제한) 신호를 사용합니다. 상단 배너·차트 컴포넌트가 없어 패널/리스트로 대체했습니다.

**기획과 다르게 구현한 이유 (세 가지로 구분)**
- **SDK·플랫폼 한계**: 가속페달 신호 없음, 시동 신호 없음(`IgnitionState` 열거형만 있고 조회 API 없음), 도로 종류·같은 도로 정보 없음, 내비 POI 검색 결과 수신 불가.
- **안전·개인정보·약관 판단**: 점수 대신 양호/주의/위험 3등급과 주된 유형만 전송, 근접 경고는 옵트인(기본 꺼짐), 서버가 없으면 무전송이고 동의 안내에 전송 대상 주소를 표시, 주행 중에는 읽기 전용 화면.
- **시간·범위상 미구현**: WebSocket 대신 3초 폴링, 방향 아이콘, 같은 도로 판정, 부팅 시 서비스 시작. 이 항목들은 SDK 가 막아서가 아니라 마감 안에 구현하지 못한 것입니다.
- **운영 서버(로컬 테스트 서버만 구현)**: 마감 때문이 아닙니다. 이 앱의 기능(점수 엔진, 근접 경고 흐름)을 보이는 데 운영 서버가 필요하지 않아 로컬 테스트 서버로 구현했고, 서비스화 단계에서 인증·TLS를 갖춘 운영 서버가 필요합니다.

**기획 대비 달라진 점**

| 원문 기획 | 구현 결과 |
|---|---|
| 과속 이벤트 | NaviHelper 의 현재 도로 제한속도(`onCurrentRoadSpeedLimit`)를 읽기 전용 리스너로 연동했다(SDK 문서 기준, 콜백은 약 1초마다 수신되나 **에뮬레이터의 모든 시험 조건(기어 D·속도 0/60/100/130km/h, 내비 안내 중, 후보 경로 표시 중)에서 값이 모두 0 이었고 0이 아닌 값은 관측하지 못함** → 제한속도 실값과 '고속 지속' 판정의 동작은 실차 확인 필요). 값이 최근 10초 안에 있으면 제한속도+20km/h 이상 10초를 '고속 지속'으로 세고, 값이 없으면 **'급격한 고속 진입/고속 지속'** 기준이 그대로 적용됨(임계값 미검증). 별도의 '과속' 유형은 없음 |
| 가속 관련 신호, 시동과 함께 자동 실행 | 가속페달 신호는 SDK 에 없어 **급가속은 속도 변화율로 추정**. 시동 신호도 SDK 에 없어(`IgnitionState` 열거형만 있고 조회 API 가 없음) 시동에 맞춘 실행은 할 수 없음. 부팅 시 서비스 시작은 에뮬레이터 탐침(`docs/research_2026-11-10.md`)에서 동작했으나 이 앱은 부팅 수신기를 구현하지 않았고, 앱 실행 후 포그라운드 서비스로 수집 |
| WebSocket 실시간 알림 | **HTTP POST 폴링(3초)**. 서버 푸시 아님 |
| 같은 도로·같은 방향(NaviHelper 도로 정보) | 도로 종류 정보는 SDK 에 없고 같은 도로 판정은 구현하지 못해 **같은 방향(8방위, 인접 포함)과 격자 중심 거리만** 사용. 평행 도로·반대편 차량도 매칭될 수 있음. NaviHelper 는 제한속도 수신에만 쓰고 도로 필터에는 쓰지 않음 |
| "왼쪽 뒤에서 접근 중" | 위치가 격자 중심으로만 전달되어 접근 속도를 알 수 없다. 그래서 "접근 중"이라고 단정하지 않고 "…차량이 있습니다"로 위치(앞쪽 등)만 안내한다(경고는 억제하지 않음). 좌우는 옆 간격 40m 이상일 때만 구분 |
| 위치는 매칭 직후 폐기 | 서버(로컬 테스트 기준)가 **15초 메모리 보관 후 폐기** |
| 점수 등급 공유 | 점수가 아니라 최근 10분 이벤트 기반 양호/주의/위험 3등급과 주된 유형만 전송 |
| 배지(개선 시 지급) | 기록에서 계산한 파생값 4종(기록 삭제 시 함께 사라짐) |
| 서버(Geohash 매칭) | 직접 구현한 **로컬 전용 Python 서버**(인증·TLS 없음, 외부 배포 안 함). 실서버 미구현 |
| 배너에 방향 아이콘 표시 | 아이콘 없이 **텍스트만**("왼쪽 뒤 · …주의"). 디자인시스템에 방향 아이콘이 없음 |
| 같은 도로 판정 | **같은 도로 필터 없음.** 위험 등급 차량을 거리순으로 골라 안내할 뿐 도로는 보지 않고 접근 속도도 알 수 없음("접근 중" 문구는 쓰지 않음) |
| 시뮬레이터 시연(2단계) | 앱 안에서 가상 주행·가상 차량 주입 [구현] |

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 내 운전 습관을 점수로 보고, 주변 위험 차량 정보를 참고해 방어 운전에 도움을 주는 것을 목표로 합니다. **사고·위험 감소 효과는 측정한 바 없으며 이 문서는 효과 수치를 주장하지 않습니다.** 오탐/미탐률도 측정하지 않았고, 참여 차량이 적을 때의 효과는 검증할 수 없습니다.
- **타깃 고객**: 고속도로 주행이 잦은 운전자, 초보·가족 운전자 (기획 원문).
- **예상 지표 [기획 가정]**: 적용 10만 대 x 설치율 15% 가정 시 MAU 약 1.2만 명, 30일 리텐션 40% 목표. 근거 자료 없는 가정이며, 시동과 함께 자동 실행되는 구조가 아니므로 자동 실행을 전제로 한 수치가 아닙니다.
- **향후 계획 (구현·검증하지 않음)**:
  - 제한속도(`onCurrentRoadSpeedLimit`) 의 0이 아닌 값을 안내 상태·주행 중(실차 등)에서 확인하고, 별도의 '과속' 유형으로 분리합니다.
  - 인증·TLS 가 있는 실서버와 허위 신고 대응, 도로(링크) 기반 매칭, 실차 데이터로 임계값·가중치 보정.

### 품질 체계 (구현 결과)
- 단위 테스트(clean 빌드): 앱(safe-radar) 147건, core 82건(고유), 서버 31건, 실패 0. 경계값·변이 확인 포함.
- 코드리뷰 4회 반복(1회차 Major 다수 → 반영, 4회차 결함 0)로 개인정보 고지 불일치·철회 경합 등을 수정.
- 독립 런타임 검증 1차(에뮬레이터, 코드 수정 없음, 수정 전 빌드): 21개 항목 **PASS 12 / FAIL 2 / UNCERTAIN 7**, 크래시·ANR 0건. FAIL 2건의 원인이던 동의 팝업 본문 잘림은 수정했고, 이 1차 수치는 현재 빌드의 결과가 아닙니다.
- 독립 런타임 검증 2차(2026-11-11 후속 검증, 에뮬레이터, 수정 후 빌드): **PASS 7 / FAIL 0 / UNCERTAIN 2**(동의 팝업 전문·스위치 동의 확인 팝업·근접 경고 문구·주행 중 조작 없음 등 PASS, 주행 중 플랫폼 오버레이 미관찰과 방향 라벨 좌/우 일부는 UNCERTAIN), FATAL 0건. 근거는 [../verification.md](../verification.md) 맨 아래 절(증거 40~63).
  - PASS 예: 권한·신호 수신, 조향 6° 이벤트, 시연 흐름(72점), 전송 본문 5키(좌표·속도·점수 없음)·정차/시연/동의 전 무전송, 철회 시 leave 요청, 서버 다운 시 정직한 안내, 프로세스 재시작 복원, 기록 삭제, 저장·로그에 좌표/식별자 없음.

### 알려진 한계 (정직한 고지)
- **검증 중 발견·수정 완료 — 동의 팝업 본문 잘림**: 독립 검증에서 첫 정차 동의 팝업 본문이 3줄에서 말줄임되어 접속 IP 노출·최대 10분 연속 위치·서버 15초 보관 등 뒤쪽 고지가 보이지 않았습니다. 디자인시스템 팝업 본문 슬롯으로 옮겨 문구 전체를 표시하도록 수정했고, 수정 빌드에서 팝업이 전문과 두 버튼("나중에", "동의하고 켜기")을 모두 보여 주는 것을 에뮬레이터 화면으로 확인했고(증거: 30), 2026-11-11 후속 검증에서도 스크롤 없이 전문이 보임을 다시 확인했습니다(증거: 40).
- **검증 중 확인된 한계 2 — 주행 중 화면 가림 [재현 안 되는 플랫폼 일시 상태로 판단, 원인 미확정]**: 독립 검증에서 60km/h 주행 시 플랫폼 오버레이("주행 중에는 사용할 수 없습니다")가 앱 화면을 가려 주행 중 화면·배너·입력 차단을 화면으로 확인하지 못했습니다. 이후 재현되지 않아 플랫폼 일시 상태로 판단했지만, 앱 측 원인이 아님을 입증한 것은 아닙니다. 2026-11-11 후속 검증에서는 D 40/50/55km/h 주행 전 구간에서 이 오버레이가 관찰되지 않아 UNCERTAIN(미발생)으로 기록했고, 같은 검증에서 주행 중 읽기 전용 화면·상단 3초 배너·주행 중 조작 없음은 에뮬레이터 화면으로 확인했습니다(증거: 40, 48, 49, 54). 오버레이의 원인은 여전히 미확정입니다.
- **미검증**: 방향지시등을 켠 차로변경이 감점되지 않는지(지시등 값을 설정할 수 없어 확인 못함), 실제 TTS 음성 청취(2026-11-11 후속 검증에서 배너 화면과 TTS 호출 문장은 로그로 확인했으나 소리는 확인 불가), 방향 라벨 중 오른쪽 계열(후속 검증에서 앞쪽·뒤쪽·바로 근처·왼쪽 뒤만 확인), **재동의 후 공유 재개 e2e**(1차 검증에서 재동의 후 위치를 받지 못해 재개되지 않았고, 후속 검증에서는 '위치 없음'이 지속되는 상태가 한 번 재현되어 `adb reboot` 후 정상화됨 — 앱 결함인지 에뮬레이터 위치 서비스 문제인지 가르지 못함), Portrait, 백그라운드 서비스·알림, 제한속도 실값과 고속 지속 판정, 앱↔서버 실기 통신의 서버 측 삭제 확인, 실차.
- 임계값·가중치·등급 기준은 실도로 데이터로 보정하지 않은 초기값이며, 조향각 6° 기준이 실차에서 맞는지 확인하지 못했습니다.
- **법률 검토를 하지 않았습니다.** 위치 기반 서비스를 상용화하려면 위치정보 관련 신고 대상 여부 확인과 개인정보 처리방침이 필요합니다. 현재는 로컬 테스트 서버와 시연 모드만 있고 외부에 배포하지 않았습니다.
- 근접 경고는 접근 속도를 알지 못하고 같은 도로 여부를 알지 못하며(허위·평행 도로 매칭 가능), 서버는 인증이 없어 허위 신고에 취약합니다.
- 서버 주소가 바뀐 빌드에서는 재동의가 필요하지만 이 버전에는 구현돼 있지 않습니다. 근접 경고 스위치를 켤 때는 전체 고지 확인 팝업을 거칩니다.
- 프로세스가 죽으면 진행 중 주행은 마지막 저장(30초 주기)까지만 기록되고, 감점 구간 시각은 재시작 뒤 횟수만 보입니다. P단 전환 후 리포트가 40~60초 뒤에 나타났습니다(경미).
- 앱이 다른 화면에 가려진 동안의 TTS는 이 앱에서 확인하지 않았습니다(WakeMate 에뮬레이터에서는 화면 밖 TTS가 나왔으나 앱·기기에 따라 다를 수 있음). 저장 데이터는 기기 내 저장(점수·시각·거리·횟수).
